### 3D 铅笔板书是怎么做的

难点是「让三维里的笔尖真的沿着笔画走」。做法是**不重写几何**，而是复用已经验证过的
`handwrite` / `vertical-calc` 引擎渲染出来的 SVG 笔画：

1. 把某一步「隐藏渲染」一次（离屏 div），从 SVG 里取出所有 `path / line / circle`；
2. 用元素自身的变换矩阵把采样点换算到 SVG 用户坐标，再映射到 3D 板面；
3. 每个笔画生成一条 `TubeGeometry`，用 `setDrawRange` 从 0 逐段「画」出来；
4. 笔尖位置 = 曲线在当前进度的采样点，小助手和长杆铅笔整体跟随。

几个踩过的坑记在这里：

- **每步都要重新采样**。竖式引擎每一步都是「整张重建」（去小数点那一步甚至会减少笔画），
  所以不能只取末步几何做叠加，否则会在错误的步骤显示出错误的数字。
- **动画要按绝对时间求值，不能逐帧累加**。预先算好一整条时间轴（抬笔 → 写字 → 抬笔 → …），
  每帧只做 `applyAt(elapsed)`。这样掉帧、切后台、拖动速度条都不会卡住或跳帧。
- **小助手不要跟着笔尖跑**，否则会挡住板书。让它固定站在黑板右侧，用「长度自适应的长杆铅笔」
  从手连到笔尖 —— 视觉上仍然像在写字，板书却完全不挡。
- **黑板宽度锁定、高度随内容生长**。缩放由整道题的最大板面决定（字号全程一致），
  每一步的板高按当前内容算，既不会每步跳动，也不会留一大片空白。

## 吉祥物 3D 模型

## 没有 WebGL 时会怎样

这一条是硬要求：**关掉 WebGL，站点必须仍然可用，而不是留一堆点不动的空壳。**

`Lab.dec3d(canvas, note)` 负责统一收尾（`js/lab-core.js`）：
藏掉画布本身、把角标从「3D」改成「2D」、把「拖动换视角」换成「本机未启用 WebGL」，
再补一句说明 —— 但**保留读数条和控件**，因为滑块与按钮背后的算式、讲解本来就不依赖 3D。

| 章节 | 3D 不可用时仍然能用 |
|---|---|
| 小数乘法 | 拖滑块仍会改变算式读数（0.7 × 0.2 = 0.14 照常显示）；「自动旋转」按钮自动收起 |
| 小数除法 | 点「两边同时右移 1 位」照常一步步算出转化结果，读数与计数同步更新 |
| 简易方程 | **完整可用**：`js/lab-3d.js` 导出的纯函数 `applyOps` 给页面一份数据镜像；没有天平，解题步骤照样一步步推，「❌ 只在左边」也会照常算出「左边 80，右边 100」并说明天平为什么会歪 |
| 铅笔板书 | 自动退回 2D 手写分步（`#wFallback`），并逐笔描出笔顺 |

三个页面的降级路径都用「关掉 WebGL 的浏览器 + 真的点一遍按钮」验证过，零未捕获异常。

## 三条必须守住的约定

1. **浅底区域的文字用墨色**。练习区是「贴在黑板上的纸」（浅底 `#f4f1e6`），
   纸面内一律用 `--ink / --ink-2`，不能沿用粉笔色系 —— 粉笔色是给深色黑板用的浅色，
   放到纸上会几乎看不见。`js/` 里也不要用已废弃的 `var(--muted)`（未定义的 `var()` 不报错，只会静默继承）。
2. **CSS 的粉笔浅色不要直接当 3D 材质色**。浅青 `#8fd8e8` 这类颜色上到 3D 表面会被光照冲成近白，
   青色竖条和粉色横条就分不出来了。3D 材质用 `PALETTE` 里另设的「彩色粉笔」饱和色
   （`0x2b9fc0` / `0xd1547a` / `0x63c46a`），环境光保持偏弱。
3. **3D 相关的功能都要有「没有 3D 也能用」的退路**。新增实验台时，除了 `Lab.dec3d`，
   还要保证按钮背后的算式与讲解不依赖 `lab` 对象。

## 自检

两个脚本，都不依赖任何第三方库，改完随手跑一遍：

```powershell
node tools/site-check.js    # 站点契约：117 项（结构 / 无障碍 / 资源 / 版本号 / 五步完整性）
node tools/math-check.js    # 题库答案：88 项断言（与竖式引擎同一份实现）
```

`site-check.js` 会拦下这些容易改漏的事：五个阶段 section 少一个、章节页漏引某个脚本、
资源版本号只升了一半（会出现「新 HTML + 旧 JS」）、画布缺无障碍标注、
`aria-describedby` 指向不存在的 id、脚本忘了 `defer`、`.stage-3d` 又把触摸滚动禁掉了。

## 质量审计（本轮改进）

**目标**：在不改变教学主线与黑板风格的前提下，把「能用」提升到「可靠」——
在没开 WebGL 的老设备上、在手机触摸操作下、在用键盘或读屏的情况下，都还能正常学习。

**维度与结论**

| 维度 | 审计发现 | 处理 |
|---|---|---|
| 健壮性 | 关掉 WebGL 后，`Lab3D` 构造失败返回 `null`，但页面多处 `lab.xxx()` 没判空；方程页的按钮甚至直接 `if (!lab) return`，点了没反应 | 统一 `Lab.dec3d()` 收尾；导出纯函数 `applyOps`，给方程页一份数据镜像，降级下功能完整 |
| 健壮性 | 两个章节页还留着旧的降级写法，用 `innerHTML` 把读数区整个替换掉，连 `#balEq` / `#balHint` 一起删了 —— 状态在变但学生看不到 | 删除旧写法，改为只藏画布、保留读数 |
| 无障碍 | 全站没有任何 `:focus` 规则，键盘用户看不到焦点位置；章节页没有 h1；3D 画布没有替代说明 | 补 `:focus-visible`、`sr-only` h1、`role="img"` + `aria-label` + `aria-describedby`、读数条 `aria-live` |
| 移动端 | `.stage-3d { touch-action: none }` 会让手指划过 3D 区域时页面**滚不动** | 改为 `pan-y`（纵向留给页面滚动，横向与双指留给 3D） |
| 准确性 | 三章都没标教材出处 | 首页卡片与页脚标注「人教版五年级上册 第 1 / 3 / 5 单元」 |
| 完整性 | 对照教材，缺「积的近似数」「商的近似数」「循环小数」「进一法 / 去尾法」「列方程解应用题」 | 全部补进已有卡片内部（不新增面板），篇幅只增加约 4 行 |
| 清晰度 | CSS 的粉笔浅青 `#8fd8e8` 被直接用作 3D 材质，被光照冲成近白 —— 面积积木台里「青色竖条」和「粉色横条」几乎分不出来 | 3D 材质改用饱和的「彩色粉笔」色，并把过强的环境光压下来（0.62 → 0.42、0.26 → 0.14） |
| 性能 | 8 个脚本全部同步阻塞首屏解析 | 加 `defer`；首页内联脚本包进 `DOMContentLoaded`，并修掉首页 `fr.onload` 式的时序隐患 |
| 可验证性 | 只有题库自检，改版容易悄悄破坏结构 | 新增 `tools/site-check.js`（117 项契约断言） |
